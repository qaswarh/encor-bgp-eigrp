BGP Knowledge Base

ENCOR 350-401 v1.2 Domain 3 reference for eBGP/iBGP rules and Best-Path Selection (WLLA OMNI).

Cisco BGP Best-Path Tie-Breakers (WLLA OMNI)

1. Weight (Cisco Proprietary — Highest Wins)

Local to the router only (never advertised to any BGP neighbor). Default is 32768 for locally originated routes and 0 for learned routes.

2. Local Preference — LOCAL_PREF (Highest Wins)

Well-known discretionary attribute shared only within the local Autonomous System (iBGP) to choose the preferred exit point. Default is 100.

3. Locally Originated (Self-Originated Wins)

Prefers a route originated by the local router via network, aggregate-address, or redistribute (Next-Hop 0.0.0.0) over routes learned from peers.

4. AS_PATH Length (Shortest Wins)

Well-known mandatory attribute listing every Autonomous System traversed. Shorter AS hop counts win unless bgp bestpath as-path ignore is configured.

5. Origin Code (Lowest Wins: i < e < ?)

Indicates how the route entered BGP: IGP (i) via network command beats EGP (e), which beats Incomplete (?) via redistribution.

6. MED — Multi-Exit Discriminator (Lowest Wins)

Optional non-transitive metric sent to neighboring ASes to suggest the preferred entry point into our AS. Default is 0; compared only between paths from the same neighbor AS by default.

7. eBGP over iBGP & Router ID

External BGP (AD 20) beats Internal BGP (AD 200). If still tied, lowest IGP metric to Next-Hop wins, followed by oldest eBGP path, then lowest BGP Router ID.

eBGP vs. iBGP Rules

iBGP Split Horizon & Next-Hop-Self

Routes learned from one iBGP peer are never advertised to another iBGP peer (preventing loops without AS_PATH changes), requiring a full mesh, Route Reflectors, or Confederations. Use next-hop-self on edge routers so internal peers can reach eBGP next-hops.

EIGRP Knowledge Base

ENCOR 350-401 v1.2 Domain 3 reference for Named Mode EIGRP, DUAL metrics, and Feasible Successors.

DUAL & Metric Terminology

DUAL — Diffusing Update Algorithm

Diffusing Update Algorithm is the loop-free path computation engine used by EIGRP. It evaluates Feasible Distance (FD) and Reported Distance (RD) to elect a primary Successor and pre-compute loop-free Feasible Successors.

Feasible Distance (FD)

The lowest total calculated metric from the local router all the way to the destination network. Displayed first in show ip eigrp topology (e.g., FD is 30720).

Reported Distance (RD) / Advertised Distance

The total metric advertised by an upstream neighbor from that neighbor's perspective to the destination. Displayed second in topology output: (FD / RD).

Successor & Feasible Successor (FS)

Successor: The primary best route (lowest FD) installed in the RIB. Feasible Successor: A loop-free backup route stored in the topology table for instant failover without querying neighbors.

Feasibility Condition (FC) — RD < FD

A backup path qualifies as a loop-free Feasible Successor if and only if its Reported Distance (RD) is strictly less than (<) the current Successor's Feasible Distance (FD).

Classic vs. Wide Metrics (64-Bit)

Classic EIGRP scales 32-bit metrics by 256 (saturating above 10 Gbps). EIGRP Named Mode uses 64-bit Wide Metrics scaled by 65536 to differentiate 10G, 40G, and 100G links.

EIGRP Stub & Stuck-in-Active (SIA)

If a route is lost and no Feasible Successor exists, EIGRP enters the Active state and sends Queries. Configuring spoke routers with eigrp stub limits query scope and prevents SIA timeouts.
